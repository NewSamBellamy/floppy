# Floppy

A cinematic Floppy foundation: an editable, scrollable disk collection and a guided Phase 1 journey from Idea through Readiness. The included preview runs locally; optional account infrastructure requires provisioning.

Serve this directory over HTTP (ES modules require a server): `py -m http.server 8766 --bind 127.0.0.1 --directory outputs` from the workspace root. Open http://127.0.0.1:8766/index.html.

In the unconfigured preview, projects, uploaded art, notes, decisions and chapter progress use local browser storage. They are device/browser-specific. Save failures and conflicting changes from other tabs are displayed. The Google key stays in the current tab and is never persisted. [CLOUD_SETUP.md](CLOUD_SETUP.md) describes the opt-in account backend; it is not live in this checkout.

The collection uses project titles directly on each label with no “Project 1” naming. Continue opens the project workspace directly. The picker’s **Edit title** control changes the workspace title, description, and disk color. The first Idea screen has a separate product name; Floppy carries it into later AI work and the brief/agent handoff. Existing projects fall back to their current title until a product name is entered. Scroll with touch, mouse, or arrow buttons.

The project workspace separates lifecycle phase from chapter. Phase 1 has 13 ordered chapters (Idea, Problem, Audience, Alternatives, Evidence, Assumptions, First Product, Product, Features, Identity, Design, Idea Brief, Readiness). Each chapter can be unresolved, drafted, or resolved by the user; resolving unlocks the next chapter, and reopening a decision locks downstream chapters again for review. A user can explicitly continue with uncertainty. Prototype becomes available only after the human Readiness decision; later lifecycle phases remain visible and locked in this iteration.

The Idea chapter uses one writing surface with optional context attachments. Other chapters can prepare a Gemini-generated Work Brief from the idea, earlier decisions, and captured context. People can attach returned research and ask Gemini for a separate proposed synthesis; they review and accept it explicitly. First Product through Design use founder-edited choices with optional AI directions. The Idea Brief derives from confirmed decisions; Readiness shows knowns, uncertainty, risks and deferrals. Context and source material are not treated as verified facts. Uploaded files are locally limited to 1 MB; only files explicitly analyzed are sent to Google's Gemini API.

The Project Art editor accepts an uploaded image or a prompt-driven Gemini candidate, with optional confirmed project context and reference images; adjust the crop and choose **Use image** to save it. Uploads and generated art remain candidates until explicitly approved. A configured account would keep the Gemini key encrypted server-side and use it through an authenticated gateway. Live account, Gemini, and encryption deployment have not been end-to-end tested.

This is not the complete PRD implementation. Prototype, MVP, Production, and Post are navigation placeholders, not fully designed workflows. Account authentication and cloud persistence have code and a migration but are not provisioned or connected to a live service. External-tool integrations and deployment verification remain outstanding. Engineering requirements remain unconfirmed; local human decisions must not be mistaken for machine verification.
