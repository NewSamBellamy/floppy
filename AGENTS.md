# Floppy implementation rules

- Preserve the existing product direction. Inspect the affected code and current behavior before editing.
- Fix causes, not symptoms; avoid accumulating CSS overrides or duplicate state.
- Preserve browser project data and migrations. Back up before risky changes.
- Keep the active question and next decision prominent. Prefer removing, combining, inferring, or disclosing controls over adding clutter.
- Keep source material, AI interpretation, and human-confirmed values distinct.
- Verify the affected journey, persistence, and relevant tests before calling a change complete.
- Checkpoint each stable milestone. Do not add unrelated features.
- Use `GOAL.md` for the finish line, `PLAN.md` for milestones, `IMPLEMENT.md` for execution, and `STATUS.md` for the live handoff.
